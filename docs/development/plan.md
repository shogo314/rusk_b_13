# 作業計画

## β11の区切り

β11は「ライブラリ拡充のための道具作り」と基本ライブラリの整備を完成範囲とします。実装とローカル検証は完了しました。経緯・合意した仕様・検証結果は[β11の開発記録](beta11.md)に保存しています。

| 分野 | 完成範囲 |
|---|---|
| 型とコピー | 空のstruct、再帰型・循環共有、__copy__への統一、struct・enumのコピー・等値比較・ハッシュの自動生成と手動優先 |
| ライブラリ作者の道具 | 独自の辞書キー、readonlyの返却値・要素・型引数、Int・Boolの値引数、型付きexternへの接続 |
| メタ情報 | 処理系の版・リビジョン・変更状態・公開元のAPI、生成C++へのRuskソース全文と識別情報の記録 |
| 既存例の標準化 | UnionFind・FenwickTree・セグメント木・PriorityQueue、剰余累乗・素数判定・Z-algorithm・LCS・グリッドBFS |
| 基本ライブラリの拡充 | BigInt、IntArray、BitVec・Bits、Deque・Array・Slice、OrderedSet・MultiSet・OrderedDict、順列・選択・整列集合・累積演算 |

通常・最適化なしの回帰検査、公開問題（AOJ 41解答・Library Checker 10解答）、リーク検査を含むASan / UBSan 100ケースが成功しています。追加ライブラリの専用テストは16組です。整形・Clippy・文書ビルドも確認しました。検証対象の正本と実行方法は[テストの実行](verification.md)を参照してください。

β12は高度なデータ構造とグラフ・文字列・数論のアルゴリズムを追加し、テストCIと文書CIを通過しました。追加した機能と開発経緯は[β12の開発記録](beta12.md)にまとめています。β13の起点はβ12の完成コミット `fe6ba14` です。

## β13で取り組むこと

Ruskの実行に必要な定義を依存関係から求め、C++への出力を絞ります。対象は関数、構造体・列挙型、extern宣言とその補助コードです。関数値、型付きextern、自動生成するコピーや比較からの参照も扱います。未使用の定義にも型検査を行います。

BigIntの高速乗算、追加のスライス対象、readonlyを含むネイティブ走査の解析精度は継続課題です。

### 出力削減前の点検

初期コミット `e36a7d2` のCLIに下表の入力を与え、通常・`--no-opt` の両方で生成C++をコンパイルして実行しました。定義の有無と件数は、最初の `// Rusk source:` 行より前で数えています。

| 入力・操作 | 初期コミットでの観測 |
|---|---|
| 空ファイル | Rusk関数の本体81個、record定義12個、enum定義7個。C++本体は通常336,625バイト、最適化なし315,749バイト |
| 空ファイルに未使用の具体関数・struct・enumを一つずつ別々に追加 | 関数の入力では本体82個、structの入力ではrecord定義13個、enumの入力ではenum定義8個 |
| 整数を返す具体externだけを宣言 | そのC++本体は出力されない。同じexternを未使用のRusk関数から呼ぶと出力される |
| 同じexternを直接呼ぶ場合と、Rusk関数値を型付きexternの `@{invoke F(T)->R}` から呼ぶ場合 | どちらもextern本体が出力され、実行結果は `42` |
| 内側のstructが独自の等値比較・ハッシュを持つ外側のstructをコピーし、コピーのフィールドを書き換える | 元の値とコピーの値は `2 12`。10を法とする内側の比較・ハッシュを外側の導出が使い、比較結果は両方 `Yes` |
| 未使用の `fn idle()->Int{return "bad";}` | 両モードで返却型の不一致を同じソース位置に報告し、C++を作成しない |

| 優先度 | 点検で分かったこと | 対応 |
|---|---|---|
| 高 | `prepare_bodies` は未使用の具体関数も検査する。その過程で解決した呼び出し先が全体の `used` に入り、`cpp_context` がextern本体の出力に使う。型の前方宣言・定義も登録表全体から生成する | β13の機能実装では、型検査後にトップレベルの実行から関数・型・externの依存をたどる。検査済み・具体化済みの情報は診断用に保持する |
| 高 | 型付きexternの参照は `compiler/externs.rs`、関数値の呼び出し口は `compiler/function_families.rs`、フィールドのコピー・比較・ハッシュは `compiler/aggregate_operations.rs` で決まる。全体の出力要求だけでは、要求した定義を区別できない | 参照元と参照先を具体化単位で記録する。フィールド型、アダプタ、効果問い合わせ、導出が必要とする操作も対象にする |
| 高 | `lib/runtime/prelude.rusk` の10個のsymbolは、それぞれ宣言済みの依存先と自分のヘッダーだけでC++20の構文検査を通る。一方、`lib/string/suffix-array.rusk` のextern本体は `__runtime_suffix_array__` が提供するC++関数を直接呼び、現状は全symbolが出力される | extern・外部型が使うランタイム資源の指定方法と、既存の利用者定義を扱う規則を決めてからsymbolを選別する |
| 中 | コンパイラとバックエンドが同じ7種類のnative出力要求を個別のフィールドで受け渡していた。recordの前方宣言も `record_forwards` と `record_cpp` で二重に出力していた | `NativeRequests` を共有し、具体化したexternの前方宣言を加える処理を保持した。recordの前方宣言は外部型・enumの定義より前の一か所に集約した |
| 中 | CIの通常・最適化なしの両スイートには `extern_callbacks`、`records`、`e2e` が含まれる。実行結果だけでは不要な定義が残っていても成功する | 具体extern単独での不出力と、同じexternを関数値経由で実行するテストを追加した。未使用関数からだけ参照したexternや未使用型の不出力は、β13の機能実装時の合格条件にする |
| 低 | 公開問題の検証ガイドはAOJを41解答としていた。READMEと実ファイルは42解答 | 現行の検証ガイドを42解答に更新した |

変更前後で同じ9入力を両モードでC++20に変換・実行しました。ビルドの変更状態を示すメタ情報を揃えてC++本体18件を比較すると、差は重複していたrecord前方宣言の削除だけでした。空入力では12行・242バイト減っています。未使用関数内の型エラーも両モードで診断が一致しました。
