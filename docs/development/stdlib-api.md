# 標準ライブラリの命名とAPI設計

標準ライブラリに公開APIを追加・変更するときの規約です。実際の署名と使い方は[標準ライブラリ](../library/index.md)を参照してください。

## 識別子の表記

| 対象 | 表記 | 例 |
|---|---|---|
| 型・列挙型のvariant | `UpperCamelCase` | `IntArray`、`RollbackUnionFind`、`Some` |
| 関数・引数・変数・フィールド | `snake_case` | `push_back`、`identity_action` |
| 定数として扱う名前 | `UPPER_SNAKE_CASE` | `MAX_SIZE` |
| ジェネリック引数 | 短い大文字、または役割が分かる `UpperCamelCase` | `T`、`K`、固定長の `N`、作用合成の `Compose` |

構築関数には型と同じ名前を使います。コンテナを操作する関数は対象を第1引数に置き、`len(values)` と `values.len()` の両方で読める署名にします。`__copy__` や `__getitem__` は言語フックの規則に従います。[言語フックの対応表](../reference/semantics.md)

## 操作名と戻り値

| 操作 | 採用する名前と意味 |
|---|---|
| 要素数・空判定 | `len() -> Int` と `is_empty() -> Bool`。読み取りだけで判定できる場合は `readonly` の値からも呼べるようにします。 |
| 取得・更新・存在確認 | 位置やキーで取得する操作は `get`、指定位置やキーへ書き込む操作は `set`、存在の判定は `contains` を使います。不在時の扱いは型ごとに明記します。 |
| 追加・取り出し | 優先度付きキューのように位置が操作から決まる場合は `push` / `pop` を使います。配列や両端キューでは `push_back` / `pop_back` など、操作する端が分かる名前を使います。 |
| 削除 | 一意のキーの削除には `erase` を使います。重複を保持する `MultiSet` は、1件の削除を `erase_one`、全件の削除を `erase_all` と呼びます。前者は削除の成否、後者は削除件数を返します。 |
| 更新と新しい結果 | 両方を提供する場合は `sort` / `sorted` のように名前で区別します。`Vec.sorted` は新しい配列を返し、その要素は元の配列と共有します。 |

関連する型で同じ操作を提供するときは、名前と戻り値の意味を揃えます。たとえば `UnionFind.unite` と `RollbackUnionFind.unite` は、どちらも実際に併合した場合だけ `true` を返します。操作の前提や効果に違いがある場合は、それぞれのAPIに記します。[配列と文字列](../library/sequences.md) · [整列コンテナ](../library/extended.md#ordered-containers) · [Union-Find](../library/data-structures.md)

## 公開APIの説明

公開宣言の `///` に、操作の結果と呼び出し側が満たす条件を書きます。該当する項目は具体的に記します。

- 引数の範囲、空入力の扱い、区間の端点。半開区間は `[left, right)` と表記します。
- 更新する対象、返り値や格納する値の共有・コピー、走査を無効化する操作。
- 不在を示す `None`、成否を示す `Bool`、実行時エラーになる条件。
- 計算量。償却計算量や、要素の比較・コピーなどにかかる費用を別に数える場合は、その前提。

公開済みの名前や戻り値を変えるときは、API文書と利用例を更新し、既存コードの置き換え方を記録します。[文書コメント](doc-comments.md) · [文書例の検証](documentation.md) · [β13の移行案内](plan.md#api)
